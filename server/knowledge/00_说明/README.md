# SRT27 知识库（KB）

本目录存放 SRT27 故障诊断智能体的本地知识资料。后端启动时递归扫描 `.md` 文件，仅将带有效元信息且已启用的资料按章节切块并建立关键词索引；用户提问时，RAG 模块检索最相关的片段注入 LLM system prompt。

## 目录约定

| 目录 | 用途 |
| --- | --- |
| `00_说明/` | 本说明与元信息 |
| `01_通用原理/` | 发动机、冷却、润滑、液压、电气、传动、制动、转向等通用机械原理 |
| `02_农机类型/` | 拖拉机、联合收割机、插秧机、植保机等类型级知识 |
| `03_新能源农机/` | 电动、混动、氢燃料农机 |
| `04_智能农机/` | 无人农机、自动驾驶、远程运维 |
| `05_故障代码/` | DTC / 故障码表与含义 |
| `06_品牌资料/` | 东方红、雷沃、中联、久保田、约翰迪尔等品牌通用资料 |
| `07_具体型号/` | 具体机型（如 MF-25D、DF-1204 等）专属维修手册内容 |
| `99_待整理/` | 临时放置、待归类的原始材料 |

资料直接放在对应分类目录下，不要在本目录内重复创建 `server/knowledge/`。当前两份有来源资料位于 `02_农机类型/拖拉机检修与常见故障.md` 和 `05_故障代码/约翰迪尔9R-诊断故障码.md`。资料引用采用相对本目录的路径，Windows 和 Linux 均使用 `/` 分隔。

## 文件格式约定

每份资料必须添加一行 `agridx-meta` 元信息，字段说明如下：

- `machineType`：前端选择器使用的中文机器类型，例如 `拖拉机`。
- `enabled`：布尔值；新增或未审核资料先设为 `false`，维护者确认适用范围后才能设为 `true`。
- `sourceUrl`：实际原文网址，供回答展示来源；新增资料应填写可核对的出处。
- `brand`、`models`：可选品牌和型号范围。专用资料只有在用户提供匹配品牌、型号且无机型冲突时才参与回答；通用资料省略这两项。

每个二级标题（`##`）表示一个完整故障主题。现象、依据、排查和安全提醒放在同一章节，不要分别拆成独立的 `## 现象`、`## 原因`、`## 处理`，以免检索只取到主题的一部分。例如：

```markdown
<!-- agridx-meta: {"machineType":"拖拉机","enabled":false,"sourceUrl":"实际原文网址"} -->
# 发动机水温过高
## 冷却液泄漏与散热器检查
现象与适用条件：
...
资料依据：
...
建议排查：
...
安全提醒：
...
```

后端会按 `##` 切块，每块作为一个候选知识片段；首个 `##` 之前的概述不参与回答。`00_说明/`、缺少有效元信息的文件以及 `enabled:false` 的资料均不参与检索。`01_通用原理/通用故障诊断.md` 是未启用的示例，不能当成已审核资料。

保存资料后重启后端，索引才会更新。进一步的机型范围约定和验收步骤见根目录 [OPERATIONS.md](../../../OPERATIONS.md)。

## 扩展

当前加载和切块代码位于 `server/knowledge/retriever.ts` 的 `loadKnowledgeBase()`。未来接入 PDF / Word / Excel / TXT 时，可在该入口增加解析层并保持 `KnowledgeChunk` 接口；目前不会直接加载这些文件格式。
